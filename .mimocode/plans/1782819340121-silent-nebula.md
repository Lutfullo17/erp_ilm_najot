# Director vs Administrator - O'quvchilar Soni Farqi Tushuntirilishi

## Muammo

Director panelfda **15 ta faol o'quvchi** ko'rsatiladi, lekin Administrator "Guruhlar Boshqaruvi" bo'limida **24 ta o'quvchi** ko'rsatiladi.

## Sabab

Bu **to'g'ri xulq** - farq quyidagi sababga ko'ra yuzaga keladi:

### 1. Director Dashboard (`AdminDashboardView`)
```python
# users1/views.py, 434-qator
context['total_students'] = Student.objects.filter(is_active=True).count()
```
**Nima hisoblaydi:** Tizimda jami **noyob (unique) faol o'quvchilar** soni.

### 2. Guruhlar Boshqaruvi (`GroupListView`)
```python
# groups_app/views.py, 69-qator
context['total_students_count'] = GroupStudent.objects.filter(
    is_active=True, group__is_active=True
).count()
```
**Nima hisoblaydi:** Faol guruhlardagi **o'quvchi-guruh a'zolik yozuvlari** soni.

## Farq Qayerdan Keladi?

**Bitta o'quvchi bir nechta guruhda bo'lishi mumkin!**

Misol:
- 15 ta noyob o'quvchi bor
- O'quvchi A → Guruh 1 va Guruh 2 da (2 marta hisoblanadi)
- O'quvchi B → Guruh 1 va Guruh 3 da (2 marta hisoblanadi)
- ... va h.k.
- Natija: 15 o'quvchi lekin 24 ta a'zolik yozuvi

## Jadval

| Sahifa | Query | Natija |
|--------|-------|--------|
| Director Dashboard | `Student.objects.filter(is_active=True).count()` | 15 (noyob o'quvchilar) |
| Administrator Dashboard | `Student.objects.filter(is_active=True).count()` | 15 (noyob o'quvchilar) |
| Guruhlar Boshqaruvi | `GroupStudent.objects.filter(is_active=True).count()` | 24 (guruh a'zoliklari) |

## Yechim (Agar Davom Ettirilsa)

Agar barcha joyda bir xil ko'rsatilsa kerak deb hisoblasangiz:

**Variant 1:** Guruhlar sahifasida ham noyob o'quvchilar sonini ko'rsatish:
```python
# GroupListView.get_context_data()
from django.db.models import Count
context['total_students_count'] = GroupStudent.objects.filter(
    is_active=True, group__is_active=True
).values('student').distinct().count()
```

**Variant 2:** Director dashboardda ham umumiy a'zolik sonini ko'rsatish (tavsiya etilmaydi).

# Teacher Panel Improvements - Implementation Plan

## Current State Analysis

The project is a **Django 6.0** ERP with:
- **Frontend**: Server-rendered HTML templates with custom CSS framework (glass-panel design), Font Awesome icons, mobile-responsive with sidebar + bottom-nav
- **Backend**: Django views (CBV + FBV), service layer pattern already exists in `grades/services.py` and `attendance/services.py`
- **DB**: SQLite/PostgreSQL, models for User, Student, Group, AttendanceSession/Record, GradeSession/Record, TelegramUser/Appeal
- **Auth**: Custom User model with Role-based (DIRECTOR, ADMINISTRATOR, TEACHER), TeacherRequiredMixin for access control
- **Bot**: Full Telegram Bot integration with `send_telegram_message()` in `bot/services.py`

**Existing teacher panel pages**: Dashboard, Groups, Messages, Schedule, Profile
**Existing teacher functionality**: Attendance marking (with time check), Grade list (read-only), Lesson plan scheduling

## Module 2: Attendance Time Control & Deadline

### Problem
`attendance/views.py` `AttendanceMarkView` already checks time window (`now < lesson_time or now > end_time`), but:
- No visual alert when class starts
- No "deadline expired" message when end_time passes
- Teacher can still access via direct URL if they bookmark it

### Changes

#### 2a. Enhanced time-check in `AttendanceMarkView.get()`
- When class just started (within first 10 min): Pass `show_start_alert=True` to template context
- When current time > end_time: Show blocking message, redirect to dashboard with error
- Add `attendance_is_locked` flag based on whether records exist and time has passed

#### 2b. Template alerts in `templates/attendance/mark_attendance.html`
- Add prominent green banner: "Dars boshlandi. Iltimos, davomatni imkon qadar tezroq oling." (shown when `show_start_alert=True`)
- Add red blocking overlay when attendance is locked: "Siz ushbu dars uchun davomatni vaqtida olmadingiz. Davomatni tiklash uchun Administrator bilan bog'laning."

#### 2c. POST time re-check
- Already exists in `AttendanceMarkView.post()` — ensure the check is consistent
- After `end_time`, POST returns error and redirects

#### 2d. Admin Override endpoint
- New view: `attendance/views.py` — `admin_override_attendance()`
- Only accessible by `AdminAccessRequiredMixin`
- Creates/updates AttendanceSession for any group/date, logs to AuditLog
- Template not needed — admin can use existing attendance page (admin already bypasses time check)

### Files Modified

## Module 4: Individual Telegram Message

### Problem
Teacher can reply to existing appeals, but cannot proactively message a student's parent.

### Changes

#### 4a. New model: `bot/models.py` — `TeacherMessage`
```python
class TeacherMessage(models.Model):
    class Status(models.TextChoices):
        SENT = 'SENT', 'Yuborildi'
        FAILED = 'FAILED', 'Xatolik'
    
    teacher = models.ForeignKey(User, on_delete=models.PROTECT)
    student = models.ForeignKey(Student, on_delete=models.PROTECT)
    parent = models.ForeignKey(TelegramUser, on_delete=models.SET_NULL, null=True, blank=True)
    message = models.TextField()
    status = models.CharField(max_length=10, choices=Status.choices, default=Status.SENT)
    sent_at = models.DateTimeField(auto_now_add=True)
```

#### 4b. Migration
- `python manage.py makemigrations bot`
- `python manage.py migrate`

#### 4c. New API view: `users1/views.py` — `send_teacher_message()`
- POST only, requires teacher auth
- Validates student belongs to teacher's groups
- Finds parent's TelegramUser via `TelegramUser.objects.filter(student=student, is_verified=True)`
- Sends via `bot.services.send_telegram_message()`
- Creates `TeacherMessage` record
- Returns JSON response

#### 4d. Integration in student detail template
- Add modal/form in `teacher_student_detail.html` for composing message
- POST to the new API endpoint via JavaScript fetch

#### 4e. Message history
- Show sent messages in student detail view
- Filter by `TeacherMessage.objects.filter(student=student, teacher=request.user)`

#### 4f. URLs
- `path('api/send-message/', views.send_teacher_message, name='send_teacher_message')`

### Files Modified
- `bot/models.py` — add TeacherMessage model
- `users1/views.py` — add send_teacher_message view
- `users1/urls.py` — add API route
- `templates/users1/teacher_student_detail.html` — add message form + history
